# Heroku Rust — дорожная карта и карта паритета

Документ фиксирует результат аудита Rust-порта против Python-оригинала
[`ZetGoHack/Heroku`](https://github.com/ZetGoHack/Heroku) и порядок дальнейшей
работы. Статусы отражают **фактическое состояние кода**, а не намерения.

Обозначения:

- ✅ — реализовано и проверено в этом репозитории;
- 🟡 — реализовано частично или с осознанными отличиями;
- ❌ — отсутствует;
- 🔒 — требует привилегий владельца по замыслу.

## 2. Критические выводы аудита

1. **Права на callback-кнопки.** До этой итерации внешние модули получали коллбэки
   без проверки прав, а карточки `.logs` и `/profile` можно было открыть по
   пересланному сообщению. Исправлено: `callback_allowed` (по умолчанию
   owner/sudo), проверки для `.logs` и `profile`, фильтрация `.help` по маске.
2. **Конкурентная запись БД.** `save()` использовал общий `*.tmp`; параллельные
   сохранения могли перетереть друг друга. Исправлено: mutex на сохранение,
   уникальное имя tmp, `fsync` файла и каталога.
3. **Потеря повреждённой БД.** При ошибке парсинга создавалась пустая база, старый
   файл затирался первым `save()`. Исправлено: файл сохраняется рядом.
4. **Неограниченные задачи.** `JoinSet` пополнялся на каждый апдейт без предела.
   Будет ограничен (см. этап 1).
5. **Watchers не имеют фильтров.** Python-модули описывают watchers декларативно;
   сейчас порт вынуждает писать `if` внутри `on_message`. Будет добавлен
   `WatcherFilter` + `watchers()`/`on_watcher()`.
6. **Выключенные модули всё равно загружаются.** `on_load` вызывается для всех;
   side effects выключенного модуля нежелательны. Будет учитываться
   `disabled_modules` + состояние загрузки.
7. **Нет `on_error`.** Ошибка команды/watcher-а логируется, но модуль не может
   отреагировать (например, откатить состояние).
8. **`accounts.json` при повреждении молча теряется.** Нужна резервная копия и
   предупреждение, как для основной БД.

## 4. Осознанные отличия

- Python-модули не исполняются: модули должны быть портированы на Rust.
- `quote_media` — ссылка с preview, а не нативная цитата (ограничение grammers).
- `.eval` использует Rhai, а не Python.
- Модули компилируются в бинарник; «горячая» загрузка — это пересборка и
  перезапуск процесса, а не импорт файла.
- `.terminal` — доверенный инструмент владельца. Фильтр опасных строк не
  считается песочницей; не давайте доступ к нему непривилегированным пользователям.

## 5. Версия схемы БД

Текущая версия — `1`, хранится в `heroku.meta.schema`:

- отсутствие версии считается `v0` и обновляется до `v1` при открытии;
- база с версией новее текущей **не перезаписывается** и не понижается;
- миграции версий и старых пространств имён (`hikka.*`, `legacy.*`)
  сохраняются на диск сразу, до этого создаётся `*.pre-migration-<ts>`;
- новая миграция добавляется в `migrate_schema` и должна быть идемпотентной.

## 6. Правила изменений

1. Сначала тесты/аудит, затем код.
2. Не удалять существующие функции ради упрощения.
3. Не добавлять зависимости без обоснования.
4. Любая новая возможность должна иметь тест или проверяемый сценарий.
5. `cargo fmt --all -- --check`, `cargo check --all-targets`,
   `cargo test --all-targets`, `cargo clippy --all-targets --all-features -D warnings`
   обязательны перед коммитом.
6. Публичный API модулей меняется только с версионированием и миграцией.
